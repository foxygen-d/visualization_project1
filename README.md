# Продажи ЖК «МБ» — аналитический дашборд (проект, вариант 1)

Файлы (все в одной папке):
- `index.html` — разметка дашборда;
- `style.css` — стили;
- `dashboard.js` — загрузка данных и все графики (d3.js v7);
- `sales.csv` — исходный датасет продаж (367 квартир).

Данные загружаются из `sales.csv` через `d3.csv`, поэтому дашборд нужно открывать через GitHub Pages или локальный сервер (`python -m http.server` → http://localhost:8000), а не двойным кликом по index.html.

## Как устроен дашборд (шаблон аналитического дашборда)
- **Осмысленный заголовок** — главный вывод.
- **Фактоиды**: выручка, потери на скидках, доля проданных, остаток в продаже.
- **Основной график — шахматка продаж.** Частица данных — квартира, визуальный атом — окно на фасаде. Каркас: этаж (по вертикали) × корпус и сторона фасада (по горизонтали). Окно цветное — продана (чем насыщеннее, тем быстрее), пустое — в продаже; ширина окна — площадь, створки — комнаты. Под фасадом — что видно из окон и доля проданных; справа — доля проданных по этажам.
- **Дополнительные графики:** динамика по неделям (сделки и выручка), менеджеры (выручка, скидки, скорость, сделки по месяцам), комнатность.
- **Кросс-фильтрация:** клик по корпусу, полоске под фасадом, менеджеру или комнатности, выделение недель мышью. Фильтры по свойствам квартиры (корпус, сторона, комнаты) сужают набор квартир, фильтры по сделкам (менеджер, недели) — набор продаж; доля проданных считается как «подходящие сделки / подходящие квартиры».

## Публикация на GitHub Pages
1. Создать публичный репозиторий и загрузить в корень все файлы: `index.html`, `style.css`, `dashboard.js`, `sales.csv`, `README.md`.
2. Settings → Pages → Deploy from a branch → `main` / `(root)` → Save.
3. Через 1–2 минуты открыть `https://<логин>.github.io/<репозиторий>/` в режиме «Инкогнито».
